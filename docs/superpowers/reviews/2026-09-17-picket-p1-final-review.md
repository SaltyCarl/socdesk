## Strengths

- **The fence is literally one module run twice.** `tools/picket/fence.py` is imported by both `assemble.py` (box) and `collectors/picket.py` (pipeline); the second pass cannot drift from the first. The schemas encode the floor structurally (`credlist.hits_7d.minimum: 3`) and have no field that could hold a pair — `test_credential_floor_is_enforced_again_in_pipeline` proves a box that skipped the fence is *refused*, not silently trimmed.
- **The delta ring is small, correct and well-tested.** `ring.py::apply_snapshot` handles baseline, same-bucket accumulation, partial and full window slides, per-entity and total clamps, and pruning; the T2 fix-round tests were shown to fail when their guarded paths were removed. In production Σ per-protocol deltas == total delta by construction (both derive from `ip_intel_proto.hits`), so `knocks_7d`, `by_protocol[].hits_7d` and `share_pct` agree exactly — R5 is harmless.
- **Honest freshness is designed in, not bolted on.** `restamp_prior` recomputes status from `sensor.exported_at`, never from the prior status; `collected_at` survives keep-prior; a collector failure raises → `run_all` records `ok:false` → gate keeps last-known-good. `test_picket_export_down_keeps_prior_with_honest_status` exercises the real `run()`.
- **12b's upstream-verification discipline was the right call** and my own fetch confirms its facts: `DEFINITIONS` shape, `ip_intel` columns, `ENABLED_PROTOCOLS` syntax, no `VERSION` file, `TNET`. I additionally confirmed that every protocol module imports only `protocol_api` (stdlib-only), so `load_proto_names` will import cleanly inside the exporter's jsonschema+geoip2 venv.
- **Colour law holds.** Zero verdict classes in any Picket component (grep clean); `MicroLabel tone="accent"` is periwinkle; bars are `bg-accent`; no emoji; `scope="col"` on all seven headers; the tests assert the absence of `text-verdict-*`.
- **No new secrets, workflow untouched** (`git diff --stat -- .github/` is empty); the collector is a keyless raw GET with a byte cap; `pipeline/http.py::http_fetch` accepts the `text=True` the collector uses.
- **Small hygiene wins:** read-only SQLite URI (`mode=ro`), `--no-push` first run in the runbook, `GIT_CEILING_DIRECTORIES` on `git describe`, `Persistent=true` on the timer, `git diff --cached --quiet` idempotency, the runbook's "treat it as bait" framing and its incident-response section (destroy → rotate deploy key → audit export-repo history).
- **Documentation is genuinely extensive and mostly accurate**; the "pre-dogfood / pending dogfood" markers (R21) are used honestly throughout.

## Issues

### Critical (Must Fix before merge)

**C1. The exporter cannot open the database on a real box — wrong filename.**
- `tools/picket/systemd/picket-export.service:10`, `tools/picket/README.md:264`, `:275` — `--db /opt/knock-knock/data/knocks.db`.
- knock-knock v3.0.0 `monitor.py`: `DB_PATH = os.environ.get('DB_DIR', 'data') + '/knock_knock.db'`, mounted `./data:/app/data` → host path `/opt/knock-knock/data/knock_knock.db`.
- `exporter.py:150` opens `file:...?mode=ro` (URI, read-only) → a missing file is `sqlite3.OperationalError: unable to open database file` on every timer tick. This is exactly the first-run class 12b existed to eliminate, and the dogfood would stall at its first step with a misleading error.
- **Fix:** `knock_knock.db` in the three places; add to README §5 a pre-check `ls -l /opt/knock-knock/data/knock_knock.db*` and a sentence naming `DB_DIR` as the upstream variable that could move it.

**C2. `_country_by_ip` crashes when the GeoLite2-Country DB is absent — and the runbook never provisions it.**
- `tools/picket/exporter.py:117-128`: `geoip2.database.Reader(geoip_db)` is unguarded; `FileNotFoundError`/`InvalidDatabaseError` aborts the run before any export is written.
- The unit passes `--geoip-db /usr/share/GeoIP/GeoLite2-Country.mmdb`. knock-knock's `geoipupdate` container downloads `GEOIPUPDATE_EDITION_IDS=GeoLite2-ASN GeoLite2-City` into the named volume `geoip-data`, not to the host path and not the Country edition. `install.sh:17` installs the `geoipupdate` package but never writes `/etc/GeoIP.conf` or runs it (knock-knock's own `.env.example` notes non-Docker installs must configure `/etc/GeoIP.conf` separately).
- Spec §5 row "MaxMind DB missing on-box → per-IP `country` omitted (optional field)" is therefore **not implemented**, and three documents assert it is (`docs/PICKET.md:268-277`, `docs/OPERATIONS.md` step 2 "simply omitted if this step is skipped", `docs/PICKET.md:873`).
- **Fix (code):** wrap the reader open in `try/except Exception` → print one stderr line, return `{}` (so `country` is omitted per spec). **Fix (runbook):** a §4/§5 step that writes `/etc/GeoIP.conf` (`AccountID`, `LicenseKey`, `EditionIDs GeoLite2-Country`), runs `geoipupdate` once, enables the package's timer, and verifies the `.mmdb` exists and is readable by `picket`. Add a pytest that calls `_country_by_ip("/nonexistent.mmdb", ["1.2.3.4"]) == {}` (RED first).

### Important (Should Fix before merge)

**I1. The second-pass sanitiser does not walk every string the schema allows** (`collectors/picket.py:34-57`).
- Unwalked: `sensor.protocols[]` (≤8 chars ×16, rendered in `PicketView.tsx:76` and `PicketTeaser.tsx:39`), `sensor.knockknock_version` (≤32, `PicketView.tsx:76`), `sensor.country`, `sensor.ring_reset_at`, `totals.since`, `by_protocol[].proto` (`PicketView.tsx:97`), `top_ips[].protocols[].proto` (`:117`), `top_ips[].country` (`:118`), `top_countries[].iso` (`:138`), and the timestamps fed to `rel()`.
- Why it matters: JSX escaping makes this unexploitable today, but the repo's load-bearing rule is defence in depth precisely because "sanitisation was declared safe" has failed here twice before. The 12b brief and DATA-SOURCES both claim "every string" passes `clean_text`.
- **Fix:** in `normalize`, map `clean_text(...)[:bound]` over every string-typed property (a small helper walking the known paths is fine — do not genericise over the schema); extend `export_hostile.json` with markup in `sensor.protocols`, `knockknock_version`, `by_protocol[].proto` and a 33-char credential (which must make `normalize` *raise*), and assert on them.

**I2. `totals.unique_ips_7d` saturates at 2,000 and is a headline KPI** (`pipeline/picket.py:72`).
- Derived as `sum(1 for r in export["top_ips"] if r["hits_7d"] > 0)` over a list capped at `CAP_IPS = 2000` (`assemble.py:19`). Any SSH honeypot sees far more than 2,000 distinct IPs a week; the tab's "Distinct IPs · 7 d" block and the teaser footer would read a flat 2,000 — a silent under-count, the opposite of the feature's honesty promise. `ring.py` already computes the true figure (`unique_ips_7d`) and `exporter.py:156` discards it.
- **Fix:** add optional `totals.unique_ips_7d` (integer ≥0, described) to `picket_export.schema.json`; in `assemble_export` set it to `sum(1 for ip, h in hits7d["ip"].items() if h > 0 and is_public_ip(ip))`; in `_panel` prefer it, falling back to the current derivation. Test with a 2,500-IP rollup (the `test_caps_are_enforced` fixture already builds one).

**I3. The box-side pass never drops the sensor's own IP; only the pipeline does, by hash.**
- `assemble.py:57-78` publishes every `is_public_ip` row. Upstream `self_redaction` (verified in `monitor.py`) scrubs credential/body *text*, not `ip_intel.ip`. A connection from the box to its own public address (owner testing, a monitor, or a compromised box probing its own honeypot) creates an `ip_intel` row with the sensor's public IP, which then lands **in plaintext in `export.json` in the public export repo** — a publication in its own right. The pipeline's compare (`collectors/picket.py:42`) keeps it out of `picket.json` only if `_public_ip()` (`exporter.py:111-114`) returned the right address; the `gethostbyname(gethostname())` fallback usually yields a private/loopback address, producing a hash that matches nothing.
- **Fix:** compute the plaintext IP once in `main`, pass it (or its hash) into `assemble_export`, and drop matching rows there — "enforced twice" then genuinely holds for this invariant. If `curl` returns nothing, refuse the export (`REFUSED (public-ip)`, exit 4) rather than hash a hostname-derived address. Correct `docs/PICKET.md:256-266` (self-redaction claim) to what upstream actually does.

**I4. `install.sh` is guaranteed to abort partway on a fresh box.**
- `tools/picket/install.sh:41` — `sudo -u picket git clone git@github.com:…` runs under `set -euo pipefail` *before* README §5 generates the `picket` deploy key and `known_hosts`; the clone fails ("Permission denied (publickey)") and lines 42–45 (chown, unit install, `systemctl enable --now picket-export.timer`) never run. A re-run after §5 recovers, but the script's own order cannot succeed first time — the same class of sequencing defect T4 fixed twice for the copy step.
- `install.sh:17` — `docker-compose-plugin` is Docker Inc.'s apt-repo package name; Debian 12 ships `docker-compose` (v1) and Ubuntu 24.04 ships `docker-compose-v2`. Very likely "Unable to locate package" → abort **after** step 1 has moved sshd and **before** ufw is configured. Verify on both named targets.
- **Fix:** clone the (public) repo over HTTPS in the script and `git remote set-url --push origin git@github.com:…` so the read works keylessly and the push uses the deploy key once it exists; move key generation + `ssh-keyscan` into the script (or make §5 a documented prerequisite like the copy step); pin package names per target (`docker-compose-v2` on Ubuntu; Docker's apt repo or `docker compose` via `docker.io`'s plugin path on Debian). Consider `apt-get install` *before* the sshd change so a package failure cannot strand a half-hardened box.

**I5. The sshd hardening is not robust on the runbook's own target OSes.**
- `install.sh:12-13` seds `Port`/`PasswordAuthentication` in `/etc/ssh/sshd_config` and restarts `ssh`. On **Ubuntu 24.04** sshd is socket-activated (`ssh.socket`) and `Port` in `sshd_config` is ignored — the verification `ssh -p 2222` fails, the operator is told to "fix sshd_config", and knock-knock later cannot bind :22. On both Debian 12 and Ubuntu, `Include /etc/ssh/sshd_config.d/*.conf` is the first directive, so a cloud-init drop-in (`50-cloud-init.conf: PasswordAuthentication yes`, common on provider images) silently wins over the sed'd line — the "key-only" claim is not guaranteed. Spec §3.1's `AllowUsers` one-admin line is absent.
- **Fix:** write `/etc/ssh/sshd_config.d/00-picket.conf` (`Port`, `PasswordAuthentication no`, `PermitRootLogin prohibit-password`, `AllowUsers <admin>`, `KbdInteractiveAuthentication no`); on Ubuntu `systemctl disable --now ssh.socket && systemctl enable --now ssh.service` (or override `ListenStream`); before the pause, print `sshd -T | grep -Ei '^(port|passwordauthentication|permitrootlogin|allowusers) '` so the operator sees the *effective* config.

**I6. The dashboard bind variable exists and the runbook sets the wrong one.**
- `install.sh:30` writes `WEB_HOST=127.0.0.1` (inert). knock-knock v3.0.0's `docker-compose.host.yml` runs uvicorn with `--host ${WEB_LISTEN:-0.0.0.0}`; `.env.example` simply does not list `WEB_LISTEN`. 12b Commit 3 (R24 fact "no host/bind variable exists") documented the firewall as the *only* control; spec §3.1 asks for `127.0.0.1` binding.
- **Fix:** `WEB_LISTEN=127.0.0.1` in `install.sh`, README §4 and PICKET.md §3 (keep the ufw rule and external `curl` check as the second layer). Also make `grep -q '^COMPOSE_FILE=docker-compose.host.yml' .env` an explicit check: host networking is what makes ufw govern 8080 — under the bridge `docker-compose.yml` the port is published `${WEB_LISTEN:-0.0.0.0}:8080:8080` through Docker's own iptables chain, which **bypasses ufw**.

**I7. Compute the export age client-side now, not in P2** (`web/src/components/views/picketModel.ts:16-21`).
- `statusCopy` reads only the pipeline-stamped `export_age_minutes`. If GitHub Actions stops (the repo's most common outage), `picket.json` freezes with `status:"live"`, "last export 25 min ago" — a flat falsehood. The ledger's cited control, the landing `FreshnessStrip`, reads `health.json`, which the same outage freezes; its "last ingest · 3d ago" is the only tell, and it is not on `/desk#picket`.
- `sensor.exported_at` is already in the payload and `rel()`-style client-side ageing is the house pattern (`PicketRoute.tsx:18`). **Fix:** `statusCopy(sensor, now = Date.now())` → age from `Date.parse(sensor.exported_at)` when finite, else `export_age_minutes`; derive the label from that age with the same 90/1440 thresholds (move `LIVE_MINUTES`/`SILENT_MINUTES` into the model as constants, mirroring `pipeline/picket.py`). Two tests: frozen payload + advanced clock → "Silent"; unparseable `exported_at` → falls back. I disagree with the BACKLOG deferral: the chip *is* the feature's honesty claim and the change is ~10 lines.

**I8. Decide the merge order versus the landing-page 404 state.**
- `SituationalBoard.tsx:201-209` gates the teaser on `useStateData('picket')`. No `picket.json` exists in `data/state/` (confirmed) and the pipeline writes none until the first successful export (`build_picket` → `None`). Merging before the box is live puts an "Unavailable — Couldn't load the Picket sensor … (HTTP 404)" panel on the public landing page for as long as the dogfood takes. The ledger marked this "intended" (house pattern), but it is a product-visible consequence the owner should choose consciously.
- **Options:** (a) merge only after the first export lands (HANDOFF already orders dogfood before merge); or (b) in `PicketTeaser`/`SituationalBoard`, treat `error === 'HTTP 404'` as `payload = null` → the honest "No sensor telemetry yet." empty, keeping real fetch errors as errors. (b) is a 3-line change and also covers a future rollback that deletes the file.
